# `cig run` on each engine, 2026-11-25: the tree-walker, the VM, the default, and the default against other languages

<!-- SPDX-License-Identifier: CC-BY-4.0 -->

The 25 programs of [`bench/compute`](../bench/compute/), run by one build of cig four ways: `cig run --engine tree`; `cig run --engine vm` with the script's module already in the tin; `cig run --engine vm` with nothing in the tin, so every run lowers the script before it runs it; and `cig run` on the default (cig-script#259's `auto`: the VM when a module is kept for the script, else the tree-walker, with a `cig __lower` left behind after a script's second run to lower it and keep the module). In the same rounds the same programs were run in Lua, LuaJIT, CPython, Node and Rust, so `cig run` as it now is by default stands beside them. It was measured for [#254](https://github.com/otmof-ops/cig-script/issues/254) and [#259](https://github.com/otmof-ops/cig-script/issues/259), which made `auto` the default `cig run` takes.

The machine is a development machine (the conditions are below), not the benchmark paper's test machine: read the ratios; the times belong to this machine. cig is built from commit `7e76bb8` (merged to `main` as `cebd9dd`, [#287](https://github.com/otmof-ops/cig-script/pull/287)) as its release workflow builds it for Linux (`cargo build --release --target x86_64-unknown-linux-musl`): no release has `auto` yet, and the build still reports itself as `cig 1.25.0`, the last release's version. [The 1.25.0 release's run](ENGINES-1.25.0.md) measured the two engines, three ways, before `auto` existed.

Every measured number here is made from the samples in [`bench/results/2026-11-25-engines/main/`](../bench/results/2026-11-25-engines/main/) by [`bench/compare/report.py`](../bench/compare/report.py), and made again by [`bench/compare/check.py`](../bench/compare/check.py), a second program written apart from the first to [the same definitions](../bench/compare/SPEC.md).

## In short

- **With its module in the tin, the VM runs the 21 compute programs in 0.48 of the tree-walker's time**, 2.10 times as fast: faster on 20, level on 1, slower on 0. It gains the most on `mandel` and the least on `strbuild`.
- **`cig run` on the default is on the VM** from a script's third run on: the measurement here is `cig-auto` beside `cig-vm`. Over the 21 compute programs the default takes 0.99 of asking for the VM directly, and 0.47 of the tree-walker's: 19 of 21 programs are faster than the tree-walker on the default, level on 2 and slower on 0.
- **A first run of the VM pays for the lowering.** With nothing in the tin a run on `--engine vm` lowers the script, verifies and loads the module, and keeps it. On the compute programs that comes to 0.50 of the tree-walker's time, faster on 18 of 21. On the default no run does the lowering itself: a script's first two runs are the tree-walker's, and the second leaves the lowering to a process of its own. [A script's first runs](ENGINES-FIRST-RUNS-2026-11-25.md) measures them.
- **Against other languages, on the default:** `cig run` takes 1.35 times Lua 5.4's time at the geometric mean of the 18 compute programs both have, 1.55 times that of LuaJIT's interpreter, 2.54 times LuaJIT's, 0.63 times CPython 3.12's and 0.22 times Node 18's. Under 1, cig took less time. [The table is below](#against-other-languages).

## How it was measured

As [the benchmark paper](BENCHMARKS-2026-11-15.md#how-it-was-measured) measures, with [`bench/compare/compare.py`](../bench/compare/compare.py):

- **A whole process.** Each time is the wall time of one `cig run`, from just before it is started until it has exited and been reaped. Start-up is in every number.
- **Every run checked.** A run counts only if it exits 0 and prints exactly the program's `.expect` file. Failed pairs: 0 in pass 1, 0 in pass 2.
- **Rounds in a random order.** In each of the 21 rounds of a pass every program runs once on every side, all 245 of them, in an order drawn from a seeded generator. A time is the median of a pair's samples over both passes.
- **One home for each side.** Each side keeps its own cig home, so one side's tin is not another's and all of them carry the same number of run records at every round, but for the one more run of each program the default's two sides make before the rounds (a run's start-up grows with its history, [#252](https://github.com/otmof-ops/cig-script/issues/252)).
- **With its module in the tin** means the checked run before the rounds lowered the script and kept its module; every timed run then loads it. **With nothing in the tin** means the side's lowered modules are removed before each run, outside the timed part, and the disk is synced.
- **On the default**, every timed run is on the VM: each program is run twice before the rounds, the second of those leaves a `cig __lower` behind, and the harness waits for it, so every timed run finds the module. That it did shows in the table: `cig-auto` beside `cig-vm`. A script's first and second runs are measured in [the first-runs document](ENGINES-FIRST-RUNS-2026-11-25.md).
- **The other languages** run the translations in [`bench/ref`](../bench/ref/), as the paper runs them: Lua 5.4.9, LuaJIT 2.1 (with `-joff` and without), CPython 3.12.3, Node 18.19.1, and Rust 1.99.1 at `-C opt-level=3`. `cig run` beside them is a bare `cig run`, in the home the paper's harness gives it; like the default above it is run twice before the rounds, so every timed run finds its module.
- **The same cig settings as the paper**: `CIG_SEAL_KEY=file`, `CIG_MAX_STEPS=0`, `CIG_REPORTS=never`, `CIG_DOCTOR=0` and `NO_COLOR=1`.
- **Pinned to one CPU.** Every measured process was given one CPU with `os.sched_setaffinity` before `exec`.
- **Rested and cooled.** After each timed run the harness rests for as long as the run took (at most two seconds), and a round starts only once the CPU package is below 70 °C (or a minute has passed). A run of most of a second at full load leaves the core hot and its clock low, and a run of a few milliseconds timed straight after it would be timed on that. Neither wait is part of any time.

## What this does not show

- **Not the paper's machine.** The paper's numbers against Lua, CPython, Node and Rust were measured on the test machine with cig 1.24.0 as released. The ratios against them here are this machine's, with the CPython and Node it has, which are older than the test machine's: they do not carry from one machine to the other.
- **Small programs, timed whole.** Most of these programs run for tens of milliseconds; on the shortest the engine is a small part of the time.
- **Not a quiet machine.** At a round's start the package was at up to 68 °C in pass 1 and 67 °C in pass 2, and the samples of many pairs vary by more than 5% (the table above). On the programs that take about 3 ms, a ratio within a few hundredths of 1 is level here, whichever side of 1 it falls: `json-deep`, counted above as faster on the VM at 0.96, is one of them.
- **A module is one build's.** The build of cig is part of the key a module is kept under, so a cig that has just been updated has a module for no script: under the default each takes the tree-walker for two runs again, and `--engine vm` lowers each on its first.
