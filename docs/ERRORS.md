# Error codes

Every diagnostic `cig` prints carries a stable code, rendered as `error[E502 runtime]: ...`, and every code is a node in one registry (`errors/registry.toml`): its family, which of the **four kinds of no** it is ([the lexicon](LEXICON.md#the-four-kinds-of-no)), what it means, what to type next, and its ranked causes, each with the read-only probe doctor uses to confirm it and the remedy. `cig explain <code>` prints the same page at the terminal; `cig explain --schema` prints the JSON Schema that `--json` output follows ([diagnostic.schema.json](diagnostic.schema.json)).

A code never changes meaning. A retired code is never reused. A code marked *planned* is reserved for a feature that has not shipped; one marked *cigo* is reported by cig-orchestrator's guard, never by cig itself. Generated by `scripts/gen-errors-doc.py`; do not edit by hand.

## The four kinds of no

| id | what you hear | whose problem | the manual's name |
|---|---|---|---|
| `none` | not one of the four | a mistake in the text, in the arithmetic, or in CigScript | syntax, type or logic error; an internal error |
| `cant-see-any` | can't see any ciggies bro | yours: you're pointed at the wrong place | wrong address: a path, a name, a directory not on PATH; ENOENT |
| `these-are-mine` | these are MY ciggies | the door: it knows you and said no | 403 Forbidden; permission denied; a lock; a refusal by policy |
| `dont-have-any` | don't have any over here | nobody's: right place, right you, nothing there | 404 from the server's side; an empty result |
| `depends` | one of the four; the message says which | read the operating-system reason in the message | ENOENT, EACCES, ENOSPC and friends, each mapped in the causes below |
| `never-heard-of-you` | never heard of you | the door: it doesn't know you | 401 Unauthorized; authentication failure |

## lex (`E100`–`E199`)

lexing: the source cannot be turned into tokens.

| code | title | kind of no | what to type next |
|---|---|---|---|
| [`E100`](#e100-lexing-error) | lexing error | not one of the four | fix the character or literal the message names; `cig language` shows the forms |
| [`E101`](#e101-unterminated-string) | unterminated string | not one of the four | close the string on the same line, or write \n for a newline inside it |
| [`E102`](#e102-unknown-escape) | unknown escape | not one of the four | use \n \t \r \0 \\ \" \$ \u{hex}; for a regex or a Windows path use a raw 'single-quoted' string |
| [`E103`](#e103-unexpected-character) | unexpected character | not one of the four | spell logic as `and`, `or`, `not`; comparisons are == != < <= > >= |
| [`E104`](#e104-malformed-number) | malformed number | not one of the four | use a float (add .0) for magnitudes beyond 9223372036854775807; -9223372036854775808 is valid with the minus directly in front |

### E100 lexing error

*lex · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

The source contains something the lexer cannot turn into tokens.

**What to type next:** fix the character or literal the message names; `cig language` shows the forms

**Known causes**, ranked; doctor checks them in this order:

1. a character or literal the lexer does not know (probe `source-line`). **Remedy:** fix it at the caret


### E101 unterminated string

*lex · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

A string literal has no closing quote on its line.

**What to type next:** close the string on the same line, or write \n for a newline inside it

**Known causes**, ranked; doctor checks them in this order:

1. the closing quote is missing, or sits on the next line (probe `string-literal-scan`). **Remedy:** close the string on the line it opened; use \n for a line break inside it
2. an escaped quote \" swallowed the closing quote (probe `source-line`). **Remedy:** count the backslashes before the last quote; a raw 'single-quoted' string has no escapes


### E102 unknown escape

*lex · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

A backslash sequence in a double-quoted string is not one CigScript knows.

**What to type next:** use \n \t \r \0 \\ \" \$ \u{hex}; for a regex or a Windows path use a raw 'single-quoted' string

**Known causes**, ranked; doctor checks them in this order:

1. a Windows path or a regex inside a double-quoted string (probe `source-line`). **Remedy:** write it as a raw 'single-quoted' string, which has no escapes at all
2. a typo in an escape (no probe; a suggestion, not a finding). **Remedy:** the escapes are \n \t \r \0 \\ \" \$ and \u{hex}


### E103 unexpected character

*lex · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

A character cannot start any token, often a C-style operator.

**What to type next:** spell logic as `and`, `or`, `not`; comparisons are == != < <= > >=

**Known causes**, ranked; doctor checks them in this order:

1. a C-style operator: && || ! (probe `source-line`). **Remedy:** spell them `and`, `or`, `not`
2. a smart quote or a non-breaking space pasted from a document; the message shows the character (probe `source-line`). **Remedy:** retype the character with a plain quote or space


### E104 malformed number

*lex · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

A numeric literal does not fit in 64 bits or is not well formed.

**What to type next:** use a float (add .0) for magnitudes beyond 9223372036854775807; -9223372036854775808 is valid with the minus directly in front

**Known causes**, ranked; doctor checks them in this order:

1. the literal is larger than 9223372036854775807 (probe `int-magnitude`). **Remedy:** add .0 to make it a float, or check whether the number is right
2. a stray character inside the number (probe `source-line`). **Remedy:** digits and single underscores only: 1_000_000

Related: `E503`.

| code | title | kind of no | what to type next |
|---|---|---|---|
| [`E200`](#e200-syntax-error) | syntax error | not one of the four | look at the caret; the message says what was expected; `cig language` shows the forms |
| [`E201`](#e201-expected-an-expression) | expected an expression | not one of the four | complete the expression; look for a trailing operator or comma |
| [`E202`](#e202-unclosed-block) | unclosed block | not one of the four | add the closing brace where the block ends |
| [`E203`](#e203-expected-end-of-statement) | expected end of statement | not one of the four | put each statement on its own line, or separate them with `;` |
| [`E204`](#e204-not-a-statement) | not a statement | not one of the four | use the spelling the hint suggests; `cig language` lists the keywords |
| [`E205`](#e205-invalid-assignment-target) | invalid assignment target | not one of the four | assign to a name, `list[i]` or `map.key` |

| [`E208`](#e208-nesting-too-deep) | nesting too deep | not one of the four | flatten it; a value this deep is better built in a loop |

### E200 syntax error

*syntax · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

The source does not follow the grammar.

**What to type next:** look at the caret; the message says what was expected; `cig language` shows the forms

**Known causes**, ranked; doctor checks them in this order:

1. parsing stopped at the caret, short of what was expected (probe `source-line`). **Remedy:** supply what was expected, or remove what was not


### E201 expected an expression

*syntax · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

A value was expected here and something else was found.

**What to type next:** complete the expression; look for a trailing operator or comma

**Known causes**, ranked; doctor checks them in this order:

1. a trailing operator or comma with nothing after it (probe `source-line`). **Remedy:** finish the expression, or delete the operator
2. a keyword used where a value should be (probe `source-line`). **Remedy:** keywords are fine as map keys and member names, not as values


### E202 unclosed block

*syntax · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

A `{` has no matching `}`.

**What to type next:** add the closing brace where the block ends

**Known causes**, ranked; doctor checks them in this order:

1. a block opened and never closed (probe `brace-balance`). **Remedy:** add `}` at the end of that block


### E203 expected end of statement

*syntax · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

Two statements share a line without a separator.

**What to type next:** put each statement on its own line, or separate them with `;`

**Known causes**, ranked; doctor checks them in this order:

1. two statements on one line (probe `source-line`). **Remedy:** put each statement on its own line, or separate them with `;`


### E204 not a statement

*syntax · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

A word that is not a keyword starts the line, usually a typo.

**What to type next:** use the spelling the hint suggests; `cig language` lists the keywords

**Known causes**, ranked; doctor checks them in this order:

1. a typo in a keyword (probe `similar-names`). **Remedy:** use the suggestion in the hint
2. a word from another language: let, var, const, def, function (no probe; a suggestion, not a finding). **Remedy:** `roll` for a variable, `stick` for a constant, `pull` for a function, `pack` for a lambda


### E205 invalid assignment target

*syntax · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

The left side of `=` is not something that can hold a value.

**What to type next:** assign to a name, `list[i]` or `map.key`

**Known causes**, ranked; doctor checks them in this order:

1. assigning to a call result or a literal (probe `source-line`). **Remedy:** assign to a name, `list[i]` or `map.key`
2. `=` where `==` was meant, inside a condition (probe `source-line`). **Remedy:** write `==` to compare


### E206 chained comparison

*syntax · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

Comparisons cannot be chained like `a < b < c`.

**What to type next:** write `a < b and b < c`

**Known causes**, ranked; doctor checks them in this order:

1. `a < b < c` read as one expression (probe `source-line`). **Remedy:** write `a < b and b < c`


### E207 empty chain

*syntax · since 1.0.0 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

A chain declares no steps.

**What to type next:** list the sticks (steps) to light: chain name { fetch, build }

**Known causes**, ranked; doctor checks them in this order:

1. `chain name { }` with nothing inside (probe `source-line`). **Remedy:** put the steps inside, one per line or comma-separated


### E208 nesting too deep

*syntax · since 1.1.1 · arises in parse*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

Brackets, parentheses or blocks nest deeper than 5,000 levels, or more than 10,000 operators are chained in one expression; the parser refuses rather than run out of stack.

**What to type next:** flatten it; a value this deep is better built in a loop

**Known causes**, ranked; doctor checks them in this order:

1. generated or pasted code with thousands of open brackets (probe `source-line`). **Remedy:** build the structure in a loop, or split it across statements
2. a generated expression with tens of thousands of chained operators (probe `source-line`). **Remedy:** split it across statements, or build the value in a loop

### E300 check error

*check · since 1.0.0 · arises in check*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

The static checker found a mistake before running anything.

**What to type next:** read the message; `cig check` shows all of them at once

**Known causes**, ranked; doctor checks them in this order:

1. the checker found the mistake at the line shown (probe `source-line`). **Remedy:** fix it there; `cig check <file>` lists every one


### E301 unknown name

*check · since 1.0.0 · arises in check*

**Kind of no:** can't see any ciggies bro (yours: you're pointed at the wrong place; wrong address: a path, a name, a directory not on PATH; ENOENT).

A name is used that was never declared in a visible scope.

**What to type next:** use the name the hint suggests, or declare it with `roll` or `stick` above this line

**Known causes**, ranked; doctor checks them in this order:

1. a typo in the name (probe `similar-names`). **Remedy:** use the suggested name
2. the name is declared later in the file, or inside another block (no probe; a suggestion, not a finding). **Remedy:** move the declaration above the first use, or out of the inner block
3. a module function called without its module: read_text instead of fs.read_text (probe `similar-names`). **Remedy:** prefix it with the module; `cig language` lists them

Related: `E307`, `E501`.


### E302 stick reassigned

### E303 effect outside burn

*check · since 1.0.0 · arises in check*

**Kind of no:** these are MY ciggies (the door: it knows you and said no; 403 Forbidden; permission denied; a lock; a refusal by policy).

A function that changes the world is called where no `burn` block encloses it.

**What to type next:** wrap the call in burn { ... }; inside a pull this is a warning, since the caller may burn

**Known causes**, ranked; doctor checks them in this order:

1. a world-changing call at the top level with no burn { } around it (probe `source-line`). **Remedy:** wrap the call in burn { ... }, or the call to the function that makes it
2. inside a pull or pack: a warning, because the caller may burn (no probe; a suggestion, not a finding). **Remedy:** nothing, if every caller burns; wrap it if the function should work from anywhere

Related: `E701`.

### E306 already declared

### E307 unknown module member

*check · since 1.0.0 · arises in check*

**Kind of no:** can't see any ciggies bro (yours: you're pointed at the wrong place; wrong address: a path, a name, a directory not on PATH; ENOENT).

A module such as `fs` has no function by that name.

**What to type next:** use the member the hint suggests; `cig language` lists every one

**Known causes**, ranked; doctor checks them in this order:

1. a typo in the member: fs.read_txt (probe `similar-names`). **Remedy:** use the suggestion in the hint
2. a function from another language's library (no probe; a suggestion, not a finding). **Remedy:** `cig language` shows what exists; text.*, fs.* and path.* cover most needs

Related: `E301`.


### E308 shell through proc.run

*check · since 1.1.0 · arises in check*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

proc.run is handed a shell (`sh -c`, `bash -c`, `cmd /C`) with a command string built at run time; that is where every injection bug in every glue script has lived.

**What to type next:** call the program directly with its arguments as a list; proc.pipe for a pipeline; proc.shell if you mean the shell and the string is yours

**Known causes**, ranked; doctor checks them in this order:

1. a value that came from outside the script is spliced into a shell command (probe `source-line`). **Remedy:** pass the value as its own argument to the program; the shell never sees it


### E309 newer than the pin

*check · since 1.2.0 · arises in check, run*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

The script is pinned to a cig older than something it uses: the pinned version would refuse the script, or run it wrong.

**What to type next:** raise the pin to the version the feature arrived in (cig pin <file> infers it), or drop the feature

**Known causes**, ranked; doctor checks them in this order:

1. the pin was written before the script started using the feature (probe `source-line`). **Remedy:** cig pin <file> rewrites the pin from what the script uses

Related: `E807`.


### E310 skipped by a hop

*check · since 1.18.0 · arises in check*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

A hop's `skip` globs leave paths out of the tin: the hop's changes under them are not kept, so it cannot undo them. That is the point for a cache the hop rebuilds anyway, and it is said so nobody skips something they needed. In the box, `skip` does nothing: the box's layer keeps every change.

**What to type next:** skip only what the hop rebuilds anyway (a cache); drop `skip` to keep those files undoable

**Known causes**, ranked; doctor checks them in this order:

1. the hop names `skip` globs on purpose, for a cache it rebuilds anyway (probe `source-line`). **Remedy:** nothing to do when the skipped paths are caches; otherwise drop them from `skip`
2. the hop is boxed, and the box keeps every change whatever `skip` says (probe `source-line`). **Remedy:** drop `skip`, or drop `box` if the hop should leave those paths out

Related: `E757`.

### E720 a rekey cannot be done

*burn · since 1.19.0 · arises in run*

**Kind of no:** one of the four; the message says which (read the operating-system reason in the message; ENOENT, EACCES, ENOSPC and friends, each mapped in the causes below).

cig tin rekey refuses because what it needs is not here, is already in use, or would launder tampering. The current key must be available (otherwise there is nothing to re-seal from), and the keeper must be one a rekey can write to (keyring or key file). An interrupted earlier rekey that left behind a seal.key.old file that is not a key is also this code. The rekey takes an exclusive lock on the tin: a second cig tin rekey while one is held is refused outright, named. Every format-3 journal and the ledger are verified under the current key before anything is re-signed; a chain that does not fit refuses the rekey, naming the run, and leaves the tampered bytes on disk so they can be looked at. The keeper swap at the end is read back: a keeper that would not carry the new key refuses, leaves both stashes on disk (every sealed object stays readable under the fallback), and a later cig tin rekey finishes the job. Nothing on disk is changed before the walk begins.

**What to type next:** put the current key back (cig tin key import), or store it where a rekey can swap it (cig config seal_key keyring); after a bad seal.key.old, move it aside and run cig tin rekey again; wait for the holder of the rekey lock; fix the tampered journal cig names before trying again

**Known causes**, ranked; doctor checks them in this order:

1. the current tin key is not available (no keyring entry, no key file, nothing on --seal-key-fd) (probe `path-exists`). **Remedy:** cig tin key import the key you exported earlier, or put the keyring entry back (cigscript/tin-seal)
2. the key came in on --seal-key-fd for this run only, so a rekey has no keeper to write to (probe `env-var`). **Remedy:** cig config seal_key keyring (or seal_key file) first, so the new key has somewhere to live
3. an earlier rekey crashed and left a seal.key.old that no longer reads as a key (probe `path-exists`). **Remedy:** move the file aside (it is in the keys directory); the rekey picks up from a clean state on the next run
4. another cig tin rekey is in progress on this tin (probe `path-exists`). **Remedy:** wait for the other one to finish; if it crashed, run cig tin rekey again and it picks up the walk
5. a run's journal, or the ledger, does not verify under the current key (probe `path-exists`). **Remedy:** the run is named in the message; investigate the edit and either put the chain back (a backup) or move the run aside before running cig tin rekey again
6. another command needed the key while a rekey was running, and the rekey outlasted rekey_wait (30 seconds by default) (probe `path-exists`). **Remedy:** wait for the rekey to finish and run the command again; cig config rekey_wait N changes how long a command waits
7. the keeper would not carry the new key (keyring write failed the read-back, or the key file could not be written) (no probe; a suggestion, not a finding). **Remedy:** both stashes stay on disk and every sealed object is still readable; fix the keeper (unlock the keyring, free space on the keys filesystem) and run cig tin rekey again to finish

Related: `E703`, `E707`, `E708`, `E709`.


### E721 the tin's key folder is not private

*burn · since 1.19.0 · arises in run, any*

**Kind of no:** these are MY ciggies (the door: it knows you and said no; 403 Forbidden; permission denied; a lock; a refusal by policy).

The keys folder beside the state root holds the seal key, the ledger and the rekey lock; for the tin's history and its sealed objects to mean anything, that folder and the files in it must be yours and closed to other users. cig refuses when they are not: a folder another user owns or others can write to; a seal.key, ledger.jsonl or rekey.lock another user owns, or one that is a symlink or not a file; a seal.key others could read or that has a second name (a hard link), checked when the key is read from it. Nothing is signed, sealed or read under it. A ledger or lock of yours that is only too open holds no secret, so cig makes it 0600 and goes on. With CIGSCRIPT_HOME under a shared parent (such as /tmp, /var/tmp or /dev/shm) the folder has a per-user name (.cigscript-keys-<uid>), so two users under the same parent never share one; a folder of yours under the old shared name, still private, stays in use. Owners are named by uid (getent passwd <uid> names them). The folder is made 0700 from the start; CIG_KEYS_DIR and CIG_SEAL_KEY_FILE point somewhere else but do not weaken the checks.

**What to type next:** a folder or file that is yours, made under sudo: chown it back to yourself. One that is not yours: move it aside (it is not your key), or set CIG_KEYS_DIR to a folder only you can write. **Known causes**, ranked; doctor checks them in this order:

1. another user owns the keys folder (someone made your per-user name under a shared parent first), or it is yours but was made under sudo (probe `path-exists`). **Remedy:** made under sudo: chown it back to yourself; not yours: you cannot use it, so set CIG_KEYS_DIR to a folder only you can write, or keep CIGSCRIPT_HOME out of a shared folder
2. the keys folder is group- or world-writable, so someone else could plant seal.key or delete the ledger (probe `path-exists`). **Remedy:** chmod 700 the folder, or set CIG_KEYS_DIR to a folder only you can write
3. seal.key is readable by group or world, so someone else may have read the key, or it has a second name (a hard link) it can be read through (probe `path-exists`). **Remedy:** chmod 600 it (a hard link: copy the key beside itself and move the copy over it), then cig tin rekey if anyone else could have read it; keep the file, a new key opens nothing the old one sealed
4. seal.key, ledger.jsonl or rekey.lock is owned by another user, or is a symlink or not a file, so a read may be redirected or the file planted (probe `path-exists`). **Remedy:** yours, made under sudo: chown it back; a link: put the real file back in place; not yours: move it aside, or set CIG_KEYS_DIR / CIG_SEAL_KEY_FILE to a path only you can write

Related: `E707`, `E720`.

### E739 the pass state cannot be trusted

### E1050 a damaged program

*usage · since 1.15.0 · arises in run*

**Kind of no:** not one of the four (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error).

This program's bytes do not match the sha256 in its trailer, its record does not read, or its trailer is not at its end: it was cut short, edited, or had bytes written after it once it was compiled, and it refuses to run. A program knows it is one even without its trailer (its record starts where its runtime's image ends), so a damaged program never runs as cig. Zero padding, or a Windows certificate table from signing, may follow the trailer. The sha256 catches damage, not tampering: programs are unsigned.

**What to type next:** compile it again (cigcompile build), or fetch it again from where it came from

**Known causes**, ranked; doctor checks them in this order:

1. the file was cut short or changed after it was compiled: a partial download, a copy that stopped, a tool that rewrote it (probe `file-hash`). **Remedy:** compare its sha256 with the one from the build, then rebuild it or fetch it again
2. something was written after the program: a tool that appends data, or a signature that is not a PE certificate table (probe `file-hash`). **Remedy:** build it again, then sign it with a tool that keeps the program's end (cig-compile#10)

Related: `E1051`.

### E1054 a program with raised rights

*usage · since 1.15.1 · arises in run*

**Kind of no:** these are MY ciggies (the door: it knows you and said no; 403 Forbidden; permission denied; a lock; a refusal by policy).
