# `cig run` on each engine, 2026-11-22: the tree-walker and the VM

<!-- SPDX-License-Identifier: CC-BY-4.0 -->

The 25 programs of [`bench/compute`](../bench/compute/), run by one build of cig three ways: `cig run --engine tree`; `cig run --engine vm` with the script's module already in the tin; and `cig run --engine vm` with nothing in the tin, so every run lowers the script before it runs it. It was measured for [#254](https://github.com/otmof-ops/cig-script/issues/254), which lets `cig run` use the VM.

This is not the benchmark paper's machine or build. The machine is a development laptop (the conditions are below), and the cig is this change's own build (`cargo build --release` on glibc; it still gives its version as 1.24.0), not a release. Read the ratios; the times belong to this machine.

Every number is made from the samples in [`bench/results/2026-11-22-engines/main/`](../bench/results/2026-11-22-engines/main/) by [`bench/compare/report.py`](../bench/compare/report.py), and made again by [`bench/compare/check.py`](../bench/compare/check.py), a second program written apart from the first to [the same definitions](../bench/compare/SPEC.md). None was typed by hand.

## In short

- **With its module in the tin, the VM runs the 21 compute programs in 0.57 of the tree-walker's time**, 1.74 times as fast: faster on 19, level on 2, slower on 0. The most is `mandel`, at 0.20; the least are `json` and `json-deep`, at 0.98 and 0.97.
- **The four start-up programs come out level**: 1.00 at the geometric mean, 1 faster, 2 level and 1 slower (`startup-0`, at 1.05). `hello` takes 2.8 ms on the tree-walker and 2.8 ms on the VM.
- **A first run costs more.** With nothing in the tin a run lowers the script, verifies and loads the module, and keeps it. On the compute programs that is 0.59 of the tree-walker's time, still faster on 18 of 21. On the four start-up programs it is 1.12 times the tree-walker's: `hello` takes 3.1 ms against 2.8. These are scripts of 4 to 14 lines; [the first runs of longer scripts](ENGINES-FIRST-RUNS-2026-11-22.md) cost far more.

## How it was measured

As [the benchmark paper](BENCHMARKS-2026-11-15.md#how-it-was-measured) measures, with [`bench/compare/compare.py`](../bench/compare/compare.py):

- **A whole process.** Each time is the wall time of one `cig run`, from just before it is started until it has exited and been reaped. Start-up is in every number.
- **Every run checked.** A run counts only if it exits 0 and prints exactly the program's `.expect` file. Failed pairs: 0 in pass 1, 0 in pass 2.
- **Rounds in a random order.** In each of the 31 rounds of a pass every program runs once on every side, all 75 of them, in an order drawn from a seeded generator. A time is the median of a pair's samples over both passes.
- **One home for each side.** Each of the three sides keeps its own cig home, so one side's tin is not another's and all three carry the same number of run records at every round (a run's start-up grows with its history, [#252](https://github.com/otmof-ops/cig-script/issues/252)).
- **With its module in the tin** means the checked run before the rounds lowered the script and kept its module; every timed run then loads it. **With nothing in the tin** means the side's lowered modules are removed before each run, outside the timed part, and the disk is synced.
- **The same cig settings as the paper**: `CIG_SEAL_KEY=file`, `CIG_MAX_STEPS=0`, `CIG_REPORTS=never`, `CIG_DOCTOR=0` and `NO_COLOR=1`.

## What this does not show

- **Not the paper's machine, and not a release.** The paper's numbers against Lua, CPython, Node and Rust were measured on the test machine with cig as released. This run compares cig with itself, on another machine, from a development build. `cig run` on the VM against the other languages waits for a run on the test machine.
- **Small programs, timed whole.** Most of these programs run for tens of milliseconds; on the shortest the engine is a small part of the time.
- **One script per run.** A cig that has just been updated lowers every script again on its first run: the cig version is part of the key a module is kept under.
